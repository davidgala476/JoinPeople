# Proyecto: JoinPeople

## Sección A: Evidencia de Campo (Discovery)

* **El Problema:** El 50% de los encuestados (5 de 10 personas) expresa tener dificultad para poder ponerse de acuerdo con una o mas personas en simultaneo o tener la dificultad para poder reservar espacios, horarios en los que puedan convivir con alguna otra persona. 

* **Resultados de la Sonda:** https://forms.gle/bDeL4kaHLc3T9L536 El analisis del siguiente formulario muestra que la coordinacion es el problema predominante en el estudio.

* **¿Qué duele?:** "La última ves que invite a mis amigos del colegio y cada uno podía en un día diferente".

* **Frecuencia:** Es un problema notable que no solo habla de la interaccion entre las personas y sus conexiones si no que recalca que se dificulta el tema de horarios y la cordinacion entre partes de un grupo.

* **La Solución Soñada:** Una plataforma que tenga la informacion de cada uno y sea capaz de crear un espacio en el que se puedan agendar eventos para que todos puedan asistir, tambien posibilite crear eventos de manera personalizada pero sea la plataforma quien agende todo de acuerdo a la informacion que brinden los usuarios de la disponibilidad que tengan. 

## Sección B: Definición de Requisitos (Definition)

### Historia de Usuario Principal

* **Quiero** como usuario de la aplicacion que gestione tiempo, espacio y otros temas para poder reunirme con mi grupo de amigos sin mucho complique y sin crear dilemas entre cada uno o confusiones cuando intentamos hacerlo manualmente nosotros. **Aparte** quiero que sea posible que la misma tenga un registro de las reuniones realizadas y sea suceptible a cambios de horarios y demas. 

### Criterios de Aceptación (Definition of Done)

1. El sistema debe permitir el ingreso de horarios y disponibilidad del usuario.
2. Las notificaciones de una fecha y lugar encontrado acorde a los intereses y disponibilidad de cada uno debe realizarse para cada integrante y lo antes posible.
3. El sistema debe permitir registrar un tipo de historial entre protocolos y cambios realizados aparte de mostrar los eventos ya culminados entre usuarios.

### Requisitos Funcionales (Draft Técnico)
* **RF-01 (Módulo de Alertas):** El sistema debe implementar un servicio de notificaciones push y/o correo electrónico para notificacion y recordatorio de nuevas reuniones.
* **RF-02 (Persistencia de Datos):** El sistema debe almacenar registros de cada usuario permitiendo un tipo de agenda y contar con un asistente virtual que de opciones de organizacion para el mismo.
* **RF-03 (Gestión Multimedia):** El sistema debe permitir tambien el conteo y registro de eventos realizados con la posibilidad de añadir informacion y contenido multimedia como un tipo de album de recuerdos si asi se desea pero que la opcion este abierta para el usuario.
